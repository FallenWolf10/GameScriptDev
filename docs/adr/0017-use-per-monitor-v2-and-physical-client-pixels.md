# Use Per-Monitor V2 and Physical Client Pixels

The packaged Operator Application and Live Run Worker will declare Per-Monitor V2 DPI awareness, and the Profile coordinate contract will use unvirtualized Physical Client Pixels for expected resolution, named regions, screenshots, templates, and absolute target points. Builder previews convert between intrinsic image pixels and displayed CSS coordinates, while Live Readiness verifies effective DPI awareness, target monitor DPI, client geometry, and capture dimensions before input. The admitted snapshot fixes the target monitor, DPI, and client dimensions for that Live Run; a display change, minimization, or client-size change releases input, preserves evidence, interrupts execution, and requires a new readiness and confirmation cycle rather than automatic restoration or continuation. Same-monitor repositioning is allowed only with unchanged client geometry and freshly verified screen-coordinate conversion. Version 1 must pass 100%, 125%, 150%, 200%, and mixed-monitor scaling tests instead of requiring 100% scaling or accepting system-DPI coordinate virtualization. This keeps Profiles portable across display scale settings without hiding capture or pointer mismatches.
