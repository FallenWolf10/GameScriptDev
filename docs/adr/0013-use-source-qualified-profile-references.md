# Use source-qualified Profile References

The Operator Application will identify every Profile Pack by both source (`Built-in` or `User`) and pack identifier instead of allowing a User Pack to shadow an equal Built-in identifier or blocking startup until one is renamed. The qualified Profile Reference is carried through selection, APIs, drafts, readiness, persisted application state, and Run Snapshots, whose content fingerprint preserves exact provenance. Copying a Built-in Pack creates an independent User Pack with portable Pack Lineage and an immutable Lineage Baseline of original structured text and asset checksums. A newer Built-in fingerprint produces a Source Update notice and deliberate three-way comparison; selected changes enter a draft, while no source update inherits, merges, blocks the existing copy, or changes runtime behaviour automatically. This keeps both Profiles visible and prevents display names or installation updates from changing what a Run means.
